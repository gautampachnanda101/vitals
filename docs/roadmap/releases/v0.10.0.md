# v0.10.0

[docs](../../index.md) / [Roadmap](../index.md) / **v0.10.0**

**Status**: Released 2026-09-06. Binaries on the
[GitHub Release](https://github.com/gautampachnanda101/vitals/releases/tag/v0.10.0);
`brew upgrade vitals` picks it up automatically.

## Scope

This is a polish release on top of v0.9.0's 013 work — the container
feature now shows **every** local runtime at once, with far more detail,
and the dashboard navigation uses a standard icon set.

- [x] **Every local runtime, together** — `vitals containers`, the
  `doctor` snapshot and the dashboard now probe Docker **and** a local
  Kubernetes context in one pass and show each as its own section, no
  toggle. `--json` `snapshot.containers` is an **array** of runtime
  reports (schema **1.6.0**); `vitals containers --runtime docker|kubernetes`
  narrows to one.
- [x] **Richer container detail** — published port mappings
  (`8080→80/tcp`), container id, image (with a shortened digest),
  uptime, and a per-container memory bar. The dashboard groups
  containers by Compose project or Kubernetes namespace, and the
  Overview page carries a Containers card summing running / unhealthy
  across both runtimes.
- [x] **Kubernetes, visually distinct** — the dashboard gives the
  Kubernetes section its own colour token and a distinct icon so a
  pod list is never mistaken for a Docker one.
- [x] **Standard sidebar icons** — the dashboard navigation switched
  from hand-rolled SVG paths to a recognised open icon set (inlined,
  still no dependency).
- [x] **Clearer command help** — every `vitals help <command>` entry
  for the resource deep-dives and the launchers got worked examples
  (`--json | jq`, `--ci`, real scenarios) instead of a bare
  `vitals <command>`. `vitals live` / `explore` / `gpu --live` now
  explain the companion-tool handoff and point at
  `vitals top` / `vitals disk` / `vitals gpu` as the no-install
  fallback when a launch fails.

## Also since v0.9.0

- Windows Docker named-pipe support is exercised in CI via
  `github.com/Microsoft/go-winio` (build-tagged, never in a
  macOS/Linux build).
- The `containers-integration` workflow's `--json` assertions were
  rewritten for the array shape, and `snapshot.containers` is always a
  JSON array (never `null`) so downstream `jq` never trips.

## Not in this release

- The 011 console-view `containers` panel.
- Container `RestartCount` trend history; Kubernetes nodes / events /
  deployments.
- A non-local / remote Kubernetes context — documented as a future
  opt-in that needs its own trust-boundary review
  (see [013's implementation plan](../items/013-container-runtime-awareness/implementation-plan.md)).
